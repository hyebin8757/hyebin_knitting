# 👟 살로몬 코리아 공식 스토어 분석 및 개선 제안서

본 문서는 살로몬 코리아(Salomon Korea) 공식 스토어의 **스포츠스타일 슈즈 컬렉션 페이지**를 기술 스택, UI/UX 디자인 인터랙션, 상품 포지셔닝, 그리고 마케팅 전환 및 성능 관점에서 면밀하게 분석하고 구체적인 실무 개선점을 제안하기 위해 작성되었습니다.

---

## 1. 홈페이지 종합 분석 요약

### ⚙️ 기술 스택 및 플랫폼 (Tech Stack)
* **기반 플랫폼**: **Shopify Plus** (글로벌 1위 E-Commerce 시스템)
* **테마**: `Showcase 7.1.0` 버전을 기반으로 고도의 맞춤 브랜드 커스터마이징 적용.
* **CS & 리뷰 솔루션**: 국내 환경에 최적화된 **채널톡(Channel.io)** 및 **크레마 리뷰(Crema)**를 탑재하였으며, 글로벌 인플루언서 리뷰 연동 솔루션인 **Loox(룩스)**를 하이브리드로 병행 운용.
* **마케팅 및 데이터 수집**: Microsoft Clarity(행동 추적), Google Tag Manager, Facebook Pixel 등을 장착하여 데이터를 기반으로 한 그로스 해킹 환경 구축.

### 🎨 디자인 및 UI/UX 시스템 (Visual System)
* **다크 미니멀 에스테틱**: 주조색 `#212121`과 다크 그레이 톤을 활용하여, 아웃도어 기어 특유의 화려하고 복잡한 기능적 컬러웨이를 왜곡 없이 선명하게 부각.
* **호버 마이크로 인터랙션**: PC 환경에서 카드 호버 시 1px 정밀 보더 포커스 전환과 동시에 평점이 페이드아웃되고 사용 가능한 사이즈 및 서브 컬러칩(Color Swatches)들이 페이드인되는 역동적인 프리미엄 화면 설계 적용.

## 2. 🔍 발견된 5대 핵심 문제점 및 개선 방향

> [!WARNING]
> 아래의 발견된 사항들은 사용자 이탈율을 증가시키고 전환율을 저해하는 치명적인 병목지점입니다. 빠른 보완을 적극 권장합니다.

### 🛑 1. 비회원(게스트) 장바구니 접근 제약 해소 (Friction)
* **문제 분석**:
  사용자가 비로그인 상태에서 장바구니 페이지(`/cart`)에 직접 접근하려고 하면 무조건 로그인 페이지(`/account/login`)로 강제 강제 리다이렉트시키는 스크립트 장벽이 존재합니다.
  ```javascript
  if (!customerLoggedIn && currentPath === "/cart") {
    window.location.href = "/account/login?return_url=/cart";
  }
  ```
  이는 탐색 중인 고객에게 로그인이라는 심각한 심리적 마찰(Friction)을 제공하여, 구매 결정 단계에 도달하기 전 **고객 이탈율을 가파르게 상승시키는 주범**이 됩니다.
* **💡 개선 제안**:
  장바구니 조회 및 수정은 비로그인 상태에서도 쿠키/세션 기반으로 자유롭게 열어두고, 최종 결제서 작성(Checkout) 직전에 로그인을 요구하거나 비회원 주문 옵션을 제안하는 흐름으로 전면 수정해야 합니다.

---

### ⚠️ 2. 호버(Hover) 시 레이아웃 흔들림 현상 제어 (UI 완성도)
* **문제 분석**:
  기본 상태 카드(`.product-block__inner`)에는 테두리 속성이 정의되어 있지 않다가, 마우스 호버 시에만 `border: 1px solid var(--color-grey-01)`가 돌발적으로 주입됩니다. 이로 인해 1px 두께가 더해져 내부의 텍스트나 이미지가 안쪽으로 1~2px 덜컥거리며 수축하는 **레이아웃 시프트(CLS) 현상**을 초래합니다.
* **💡 개선 제안**:
  평소 상태에 보이지 않는 투명 보더(`border: 1px solid transparent`)를 선언하여 영역을 선점한 뒤, 호버 시 테두리 색상(`border-color`)만 부드럽게 트랜지션 처리하는 정석적인 구조로 리팩토링합니다.
  ```css
  /* 개선 제안 스타일링 */
  html:not(.touch) .product-block .product-block__inner {
    border-radius: 4px;
    overflow: hidden;
    transition: border-color 0.4s ease;
    border: 1px solid transparent; /* 공간 선확보 */
  }
  html:not(.touch) .product-block:hover .product-block__inner {
    border-color: var(--color-grey-01); /* 트랜지션 가속화 */
  }
  ```

### 🚀 3. 과도한 스크립트 종속성 및 jQuery 의존성 제거 (성능 최적화)
* **문제 분석**:
  * 플랫폼의 서드파티 스크립트들과 위젯(룩스, 크레마, 채널톡, 마이크로소프트 클래리티 등)이 중첩되어 브라우저 초기 로딩 속도(FID 및 LCP)에 저사양 디바이스/모바일 기기에서 극심한 병목을 유발합니다.
  * 특히, 단순한 모달 및 페이지 경로 제어(약 20줄)를 위해 무거운 **jQuery 3.7.1** 라이브러리를 동적으로 여전히 호출하여 전체 번들 용량을 불필요하게 가중시킵니다.
* **💡 개선 제안**:
  * 제이쿼리로 짜여진 돔 제어 및 리다이렉트 스크립트를 순수 모던 자바스크립트(**Vanilla JS**)로 변경해 **제이쿼리 CDN 로드 의존성을 원천 제거**합니다.
  * 모든 서드파티 스크립트는 첫 화면 렌더링에 영양을 주지 않도록 `requestIdleCallback`이나 `defer` 속성을 부여하여 렌더 블로킹을 해제해야 합니다.

### 📱 4. 모바일 화면 가독성 및 스와치 복잡도 조절 (Mobile UX)
* **문제 분석**:
  모바일 해상도 화면은 가로 폭과 깊이가 협소함에도 불구하고 하위 노출 컬러 스와치 썸네일 이미지 파일(`.as-collection__imageSwatchWrap--mobile`)들이 생략이나 요약 필터링 없이 한꺼번에 무더기로 늘어집니다. 이로 인해 세로 스크롤 길이가 비정상적으로 길어지고 탐색 피로도가 급증합니다.
* **💡 개선 제안**:
  모바일 리스트 스와치 칩 개수를 **최대 4개까지만 노출**하고, 초과되는 색상은 `+3` 같은 직관적인 심플 카운터 버튼으로 치환하여 클릭 시 펼쳐지는 형태의 축약형 UX로 가독성을 정돈합니다.

### ♿ 5. 시각 장애인을 위한 대체 텍스트(A11y) 확보 (웹 접근성)
* **문제 분석**:
  브랜드 고유의 투톤 혼합 색상을 미려하게 묘사하는 대각선 그라데이션 컬러칩(`.cc-checkbox__color` 및 `.as-productColors__dot`)들은 순수 CSS 백그라운드로만 칠해져 있습니다. 이로 인해 시각장애인용 화면 낭독기(스크린 리더) 사용 시 대체 텍스트가 읽히지 않아 어떤 색상 옵션인지 전혀 알 수 없는 접근성 위배 상태가 발생합니다.
* **💡 개선 제안**:
  그라데이션 및 컬러 스와치 이미지 엘리먼트마다 웹 접근성 표준 규격에 맞게 상세한 대체 설명 속성(`aria-label="블랙 / 바닐라 아이스 투톤 배합 컬러 옵션 선택"`)을 명확히 확보해 주어야 합니다.
